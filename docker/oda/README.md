# ODA File Converter в Docker-образе — опциональный шаг

**Статус: ОПЦИОНАЛЬНО.** Образ собирается и работает без этого шага — просто
на входе `pipeline.run` тогда должны быть уже готовые DXF (а не DWG). Реальный
датасет проекта — почти сплошь DWG (см. `docs/DATA_STRUCTURE.md` §3), поэтому
для полноценной демонстрации на реальных объектах этот шаг нужен, но не блокирует
сборку/тесты пайплайна как таковые.

## Почему не автоматизировано полностью

ODA File Converter — бесплатный, но **лицензируемый по клик-through EULA**
продукт Open Design Alliance. Скачивание требует явного согласия с лицензией на
их сайте — это НЕ pip-пакет и не файл со свободной прямой ссылкой, которую можно
было бы зашить в `Dockerfile` и тянуть автоматически при каждой сборке (это было
бы и хрупко — ссылка может измениться/устареть, — и, вероятно, в обход условий
распространения ODA). Тот же принцип уже применён к Windows dev-машине: конвертер
там тоже был установлен вручную, не автоматически (`docs/DATA_STRUCTURE.md` §9).

## Как добавить (один раз, вручную)

1. Открыть <https://www.opendesign.com/guestfiles/oda_file_converter> и
   согласиться с лицензией.
2. Скачать **Linux AppImage, 64-бит** сборку (НЕ .deb — см. ниже почему).
   На момент написания на Windows dev-машине установлена версия **27.1.0**
   (`ODAFileConverter_QT6_lnxX64_...AppImage` — конкретный номер сборки может
   отличаться, это нормально, лишь бы формат был AppImage).
3. Положить скачанный файл прямо в эту папку: `docker/oda/`.
4. Пересобрать образ: `docker compose build` (или `docker build .`).

Dockerfile сам обнаружит файл по маске `docker/oda/ODAFileConverter*.AppImage`,
распакует его на этапе сборки (`--appimage-extract`) и настроит
`ODA_FILE_CONVERTER_PATH` — никаких других действий не требуется.

## Почему AppImage, а не .deb

Официальная документация ezdxf (аддон odafc) рекомендует именно AppImage для
headless/Docker-сценариев — он самодостаточен (не тянет зависимости через apt,
которые могут отсутствовать в slim-образе) и не требует `dpkg`/разрешения
конфликтов пакетов. См.
<https://ezdxf.readthedocs.io/en/stable/addons/odafc.html>.

**Важная деталь**: AppImage по умолчанию монтирует себя через FUSE, а в
контейнере `/dev/fuse` обычно недоступен. Поэтому Dockerfile распаковывает
AppImage на этапе СБОРКИ (`--appimage-extract` → `squashfs-root/`), и в
рантайме используется уже распакованный `squashfs-root/AppRun` — FUSE вообще
не нужен.

## Проверка

После сборки — `docker compose run --rm app python -m pipeline.ingest.dwg_convert`
(или любой вызов, использующий `convert_dwg_to_dxf`) должен видеть конвертер
через `find_oda_converter()` — переменная `ODA_FILE_CONVERTER_PATH` уже
проставлена `entrypoint.sh` автоматически, если распакованный конвертер найден
по стандартному пути.

**Не проверено вживую в этой сессии** — на dev-машине установлен только
Windows-вариант конвертера, Linux AppImage никогда не скачивался (см.
`docs/SESSION_LOG.md`, запись про Docker-упаковку). Логика написана по
документации ezdxf и стандартной практике распаковки AppImage в контейнерах,
но byte-for-byte не прогнана на реальном DWG внутри контейнера — это открытый
пункт, см. `docs/CHECKLIST.md`.
