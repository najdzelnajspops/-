# Сборка, запуск и проверка на MosTex.OS

Обязательный документ по ТЗ (`docs/TASK_BRIEF.md`, §6.5: «инструкция по сборке/запуску/проверке, пошагово: Docker-команды, как прогнать DXF и получить результат на MosTex.OS»).

## Честная оговорка

У нас нет доступа к реальной машине с MosTex.OS для проверки — инструкция ниже проверена на **Ubuntu (WSL)** и на **Linux-контейнере Docker** (`python:3.14-slim-bookworm`, Debian). По описанию ТЗ (`docs/TASK_BRIEF.md`, §5) MosTex.OS «по среде исполнения близок к Ubuntu», поэтому шаги ниже должны работать без изменений, но это не подтверждено на самом MosTex.OS — см. `docs/LIMITATIONS.md`.

## Шаг 0 — что нужно на машине заранее

- Docker и Docker Compose (обычно уже есть на серверных Linux-сборках).
- (Опционально, только если нужно принимать сырые DWG, а не уже готовые DXF) — ODA File Converter, Linux-сборка (AppImage). Лицензия закрыта EULA-формой на сайте ODA, поэтому не входит в образ автоматически — положить файл вручную по инструкции в `docker/oda/README.md` до сборки образа. Без этого шага сервис всё равно полностью работает с DXF-файлами напрямую — только DWG не конвертируются.

## Шаг 1 — получить код на машину

Скопировать/склонировать репозиторий целиком на машину с MosTex.OS.

## Шаг 2 — собрать образ

```bash
docker compose build
```

## Шаг 3 — проверить, что всё собралось корректно

```bash
docker compose run --rm app python -m pytest tests/ -q
```

Ожидаемый результат: подавляющее большинство тестов зелёные; несколько `skip` — честно, а не ошибка: пропускаются тесты, которые требуют ODA File Converter или полный сырой датасет (23 ГБ, не входит в репозиторий), которых в чистом образе нет.

## Шаг 4 — прогнать пайплайн на тестовом DXF

Положить входной(-ые) DXF-файл(ы) в `data/` (том `./data:/app/data` уже смонтирован в `docker-compose.yml` — файлы внутри контейнера видны по пути `/app/data/...`), затем:

```bash
docker compose run --rm app python -m pipeline.run \
  --input /app/data/<входной_файл_1>.dxf /app/data/<входной_файл_2>.dxf \
  --base-dxf /app/data/<файл_с_границей_участка>.dxf \
  --territory-category dvorovye \
  --output-dxf /app/data/out/result.dxf \
  --output-report /app/data/out/report.json
```

Результат появится на хост-машине в `data/out/result.dxf` и `data/out/report.json` (том общий, файлы не остаются только внутри контейнера).

## Шаг 5 — проверить результат

- **`report.json`**: `summary.total_points` должно быть больше 0 (если участок совсем маленький или полностью занят коммуникациями — может быть честный `0` с объяснением причины, это не баг); у каждой записи в `placements` — поле с обоснованием и ссылкой на норму.
- **`result.dxf`**: должны появиться новые слои `GREEN_AI_TREE_PROPOSED`/`GREEN_AI_SHRUB_PROPOSED` (и `_REJECTED`, если что-то было отклонено) — при этом все исходные слои и объекты должны остаться неизменными (это отдельно проверяет агент ОТК внутри самого прогона, см. `pipeline/otk/layer_integrity.py`).
- **Открытие в CAD-просмотрщике** — подтверждено (2026-09-24): результат на реальном объекте открыт в ZWCAD Viewer (Windows, AutoCAD-совместимый) без ошибок, схема отобразилась корректно (см. `docs/LIMITATIONS.md`). Открытие именно на самом MosTex.OS/Linux (например, nanoCAD для Linux) по-прежнему не проверено — нет доступа к реальной машине с этой ОС; но файл — валидный DXF (ACAD2018), уже прочитан настоящим CAD-приложением семейства AutoCAD, а не только программно через `ezdxf.readfile()`.

## Второй режим (проверка человеческого выбора)

```bash
docker compose run --rm app python -m pipeline.review_run \
  --input /app/data/<входной_файл>.dxf \
  --territory-category dvorovye \
  --proposals /app/data/proposals.json \
  --output-report /app/data/out/review_report.json
```

`proposals.json` — список предложенных человеком посадок (id/вид/жизненная форма/координаты), формат см. в докстринге `pipeline/review/placement_review.py`.

## Веб-UI (второй способ запуска, не обязателен по ТЗ)

```bash
docker compose up web
```

Открыть `http://<адрес_машины>:8000` в браузере. Подробности по режимам, печати, загрузке своих файлов и обновлению цен — в основном `README.md`.
