## ППМ № 623-ПП, Приложение В «Озеленение территории» — найден основной ассортимент по категориям территорий

**Статус: `verified`.** Пропущено при первом проходе по документу (искал только по ключевым словам «озелен»/«насажд» в плоском тексте) — пользователь прямо указал, что в 623-ПП должен быть основной ассортимент по категориям территорий, и оказался прав: отдельное большое Приложение В (почти 1050 строк исходника), с таблицами В.1–В.7:

- **Таблица В.1** — максимальное количество деревьев/кустарников на 1 га по типу территории (парки, скверы, бульвары, дворы, школы, улицы и т.д.) — плотность посадки.
- **Таблица В.2** — доля цветников от площади озеленения (парки 2–2.5%, скверы 4–5% и т.д.).
- **Таблица В.3** — минимальная доля озеленения участков по типу застройки (детсады ≥50%, школы ≥40% и т.д.).
- **Таблица В.4** — ПДК загрязнения воздуха для зелёных насаждений (по газам).
- **Таблица В.5** — снижение уровня шума в зависимости от ширины полосы насаждений.
- **Таблица В.6 «ВИДЫ РАСТЕНИЙ В РАЗЛИЧНЫХ КАТЕГОРИЯХ НАСАЖДЕНИЙ»** — главная находка: 74 вида (49 деревьев, 24 кустарника, 1 лиана) с рекомендацией (+/-/с оговоркой) для 5 категорий территорий — садов/парков, скверов/бульваров, улиц и дорог, внутриквартальных, специальных.
- **Таблица В.7** — стандарты посадочного материала (крупномерные деревья, размер кома, количество пересадок).

**Про извлечение Таблицы В.6 — важная техническая деталь**: первая попытка (по плоскому тексту, тем же способом, что и остальные акты) дала НЕОДНОЗНАЧНУЮ разбивку — у части видов оказывалось 6 строк-значений вместо 5 из-за того, что оговорки вроде «с огр.» иногда переносятся на отдельную строку внутри той же ячейки, а иногда добавляют лишнюю строку. Автоматический парсинг по числу строк дал бы риск сдвига данных у части видов без возможности это заметить. Решение — переоткрыл файл через `python-docx` и прочитал таблицу по её РЕАЛЬНОЙ структуре (80 строк × 6 столбцов, ячейка = ячейка), а не по плоскому тексту — так снят риск неоднозначности полностью.

**Важно отделять от вопроса о глубине корней** (см. `docs/ARCHITECTURE.md` §3.1b, `docs/OPEN_QUESTIONS.md`): эта таблица отвечает на вопрос «какой вид рекомендован для какого типа территории», а не «какая у вида глубина/агрессивность корневой системы». Пометка «с огр.» в самом документе не объясняет причину ограничения — не домысливать, что это именно про корни (может быть пух, аллергенность, ломкость ветвей и др.). Хотя есть согласующиеся сигналы: «Ива ломкая» (известна агрессивными корнями) — не рекомендована для улиц/дворов/спецзон; «Пузыреплодник калинолистный» — не рекомендован для парков/скверов/улиц ПО ЭТОЙ таблице И одновременно числится инвазивным по 369-ПП (два независимых источника, согласованный сигнал, не противоречат).

Машиночитаемый сид: `data/reference/species_territory_recommendations.json`, код — `pipeline/catalog/species_territory_recommendations.py`.

## Постановление Правительства РФ от 24.02.2009 № 160 — охранные зоны ЛЭП

**Статус: `verified`. Источник: `docs/tz_source/normative_acts/Постановление...160...pdf`, п. 21-22.**

Закрывает вопрос №3 из списка уточнений у организаторов — точная ширина охранной зоны воздушных линий электропередачи по классу напряжения:

| Класс напряжения, кВ | Ширина зоны, м (в каждую сторону от крайних проводов) |
|---|---|
| до 1 | 2,0 (для линий с самонесущими/изолированными проводами по стенам зданий — отдельная норма) |
| 1–20 | 10,0 (5,0 — для линий с самонесущими/изолированными проводами в границах населённых пунктов) |
| 35 | 15,0 |
| 110 | 20,0 |
| 150, 220 | 25,0 |
| 300, 500, ±400 | 30,0 |
| 750, ±750 | 40,0 |
| 1150 | 55,0 |

Подземные кабельные линии электропередачи — 1,0 м от крайних кабелей в каждую сторону (для линий до 1 кВ в городах под тротуарами: 0,6 м в сторону зданий, 1,0 м в сторону проезжей части).

**Важное регулятивное уточнение**: это охранная зона объекта электросетевого хозяйства (ограничение хозяйственной деятельности, требует согласования с сетевой организацией для работ внутри неё) — самостоятельная норма, отдельная от арборикультурного отступа дерева/кустарника по 743-ПП/Таблице 3.6.1. Обе нормы применяются одновременно; для ЛЭП на практике действует более широкая из двух зон. Ширина по 160-ПП одинакова для дерева и кустарника (это зона ограничения вообще, не дифференцированный отступ по виду насаждения).

Машиночитаемый сид: `data/reference/lep_protection_zones.yaml`, реализация — `pipeline/constraints/lep_zones.py`.

## Отступ от существующего сохраняемого насаждения — практическое допущение (не норма)

## Красные линии — зона запрета размещения насаждений (практическое решение проекта, не норма)

**Статус: `assumption_not_verified_norm`** — по прямому решению пользователя (владельца проекта), 2026-09-17: «красные линии - зона запрета размещения насаждений». 743-ПП (и вообще ни один из 12 присланных актов) отступов/запретов, связанных именно с красными линиями, не содержит — это самостоятельное градостроительное ограничение (юридическая граница между территорией участка и улично-дорожной сетью), а не арборикультурная норма.

Реализовано как `explicit_distance_m=0.0` на всей нарисованной площади слоя «Красные линии» (`pipeline/constraints/red_lines_policy.py`) — не «отступ N метров от линии», а «сама нарисованная площадь запрещена». `explicit_citation` сознательно НЕ устанавливается (как и для существующих насаждений выше) — в отчёте это обязано выглядеть как `verified: false` с честным плейсхолдером, а не как цитата 743-ПП.

**Техническая находка по пути (2026-09-17, на реальном объекте «Камчатская улица»)**: слой «Красные линии» на практике нарисован не одним полигоном, а ~4000 мелких HATCH-плиток (плюс ~4000 REGION — не поддержаны, ACIS-геометрия) — потребовалось добавить обработку сущности HATCH в `pipeline/ingest/dxf_ingest.py` (её раньше не было вообще, слой красных линий был `unclassified`). См. `docs/DATA_STRUCTURE.md` §11.5 для деталей.
